Help and Support

MobileD Android App is a controller for MobileD lighting units. The following checks follow the same functional structure used by the MobileD PC App.

Getting started

  • Make sure the MobileD units and the Android device are connected to the network.
  • Use the + button on Home to run an explicit discovery scan and add new MobileD units.
  • Discovery remains active after startup and updates registered devices automatically.
  • Open an online device or group to enter the Controller. Offline devices remain saved but cannot receive commands.

Devices and Groups

  • Devices are identified by their stable MobileD identity (APName). If a known MobileD changes IP address, the saved device is updated instead of duplicated.
  • All Devices is the system group and uses GPort 8890.
  • User-created groups use their configured GPort.
  • Pixel ID defines the position used by distributed Matrix and Music effects and is independent from DMX addressing.
  • Multiple group members may use the same Pixel ID. Synchronized Legacy, Matrix and Music use consecutive Pixel IDs starting at 0 and stop before the first missing ID; every selected member sharing a participating ID is included.
  • Selecting a group keeps the members online at that moment. Commands use their current network address and skip members that are no longer reachable. Select the group again to include other members.

Controller

  • Color provides Hue, Color Brightness and White Brightness controls, plus ten saved-color slots arranged in two rows of five. Tap a saved slot to recall it; press and hold to save or overwrite it with the current color and both brightness values. The original five saved colors are retained when updating.
  • Effects contains the legacy MobileD effects and their parameters. Without a configured Master, Legacy runs locally on all selected reachable members, even with missing, invalid or non-consecutive Pixel IDs. Master/Slave roles are not required.
  • Matrix is available for valid distributed groups and uses the configured Master/Slave routing.
  • Music is App-driven: the Android device captures playback audio, generates the virtual strip and transmits the resulting DMX/sACN data to the configured MobileD group.
  • Discovery is the source of truth for the displayed device state.

Configuration

  • When editing a group, assign the required Pixel IDs and Master/Slave roles according to the selected function.
  • To synchronize Legacy, configure exactly one Master with Pixel ID 0. The Master must be selected and reachable; only consecutive Pixel IDs from 0 participate. A missing or invalid configured Master must be corrected before synchronized Legacy can start.
  • For Matrix, exactly one Master is required and the Master must use Pixel ID 0.
  • Music does not use Master/Slave. It uses the group's Pixel IDs and virtual strip routing.

Troubleshooting

  • If a device is not responding, verify that it is powered, connected to a reachable network, and visible in Discovery.
  • If a device has moved to another IP address, run the explicit discovery scan. The stable device identity prevents duplicate entries.
  • If synchronized Legacy cannot start, check that the configured Master has Pixel ID 0 and is selected and reachable. Select the group again after the Master returns online. To run unsynchronized Legacy, remove the configured Master; Pixel IDs are then optional.
  • If Matrix or Music is unavailable, verify that the selected group has valid consecutive Pixel-ID positions starting at 0 and the required GUniverse configuration.
  • If Music does not start, verify Android playback-capture authorization and that a reachable MobileD group is selected.
